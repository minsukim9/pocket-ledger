## 데이터 디렉터리

기본 저장 위치는 프로그램 소스 위치가 아니라 **명령을 실행한 현재 디렉터리의 `./data`**입니다. `--data-dir DIR`로 각 명령의 저장 폴더를 바꿀 수 있습니다.

```text
data/
├── transactions.csv     # 거래
├── categories.csv       # 허용된 카테고리
├── budgets.csv          # 월 예산
├── recurrences.csv      # 매월 반복 규칙
└── backups/             # backup 실행 시 생성
    └── backup-YYYYmmdd-HHMMSS/
        ├── transactions.csv
        ├── categories.csv
        ├── budgets.csv
        └── recurrences.csv
```

일반 명령을 처음 실행하면 없는 폴더와 파일을 만들고 헤더를 기록합니다. `categories.csv`가 없거나 **비어 있으면** `food`, `transport`, `rent`, `salary`를 자동 등록합니다. 다른 3개 파일은 기본 행 없이 헤더만 생성합니다. `backup`은 기존 저장 파일이 하나도 없는 폴더에서는 오류를 출력합니다.

**내부 저장 파일은 UTF-8, 헤더 포함 CSV**입니다(쓰기 시 LF 개행; BOM 없음). 읽기는 UTF-8 BOM이 있어도 처리합니다. 내부 CSV 헤더는 아래 스키마와 같아야 합니다(컬럼 순서는 바뀌어도 됨). 헤더·행의 컬럼 수 또는 CSV 인용 문법이 잘못되면 읽기를 중단합니다. 수동으로 편집한다면 원본을 먼저 백업하세요.

### 내부 CSV 스키마

| 파일 | 헤더(기록 순서) | 설명 |
| --- | --- | --- |
| `transactions.csv` | `id,type,date,amount,category,memo,tags` | 수입/지출. `id`는 현재 파일에서 중복되지 않아야 함 |
| `categories.csv` | `name` | 등록된 카테고리 이름 |
| `budgets.csv` | `month,amount` | `month`별 예산(양수 정수) |
| `recurrences.csv` | `id,type,category,amount,day,memo` | 월 반복 규칙, `day`는 1~31 |

**거래 필드**

| 컬럼 | 규칙 |
| --- | --- |
| `id` | `TX-000001` 형태, 기존 최대 번호 + 1 (최소 6자리) |
| `type` | `income`(수입), `expense`(지출) |
| `date` | 존재하는 날짜 `YYYY-MM-DD` (예: 2024-02-30은 오류) |
| `amount` | 1 이상의 정수; 음수·0·소수 불가 |
| `category` | `categories.csv`에 등록된 이름 |
| `memo` | 빈 문자열 가능 |
| `tags` | 쉼표로 구분한 문자열, 빈 문자열 가능 (예: `meal,weekday`) |

내부 거래 파일은 날짜 내림차순, 날짜가 같으면 **숫자형 ID 내림차순**으로 기록합니다. 파일을 임의로 재정렬하면 조회 결과도 바뀝니다. ID는 **현재 파일의 최대값** 기준이므로 최대 ID의 거래를 삭제한 뒤 다시 추가하면 그 ID가 재사용될 수 있습니다. 삭제 이력을 포함한 영구 고유 ID가 필요한 서비스 용도에는 이 정책이 적합하지 않습니다.

태그 값 `meal,weekday`는 CSV 안에서 `"meal,weekday"`처럼 인용됩니다. CSV 문법의 쉼표와 태그 구분의 쉼표는 서로 다른 층위이므로 `csv` 모듈을 사용해 읽고 써야 합니다.

## import/export 교환용 CSV

내부 파일과 달리 **교환용 CSV에는 ID가 없습니다.** 인코딩은 UTF-8, 헤더 포함. 내보낼 때 헤더는 정확히 다음 순서입니다.

```csv
date,type,category,amount,memo,tags
2024-01-15,expense,food,15000,점심,"meal,weekday"
2024-01-14,income,salary,3000000,월급,
```

| 컬럼 | 필수값 | 설명 |
| --- | --- | --- |
| `date` | 예 | `YYYY-MM-DD` |
| `type` | 예 | `income` / `expense` |
| `category` | 예 | 등록된 카테고리(입력 시 대소문자 무시 후 등록 표기로 저장) |
| `amount` | 예 | 1 이상의 정수 |
| `memo` | 아니요 | 메모; 빈 값 가능 |
| `tags` | 아니요 | 쉼표로 구분한 태그; 빈 값 가능 |

가져오기에서는 `date`, `type`, `category`, `amount` **헤더가 필수**이며 `memo`, `tags` 헤더는 생략할 수 있습니다. 헤더 중복/필수 헤더 누락, 해석 불가능한 인용 문법, 읽기 실패는 파일 단위 오류입니다(이 경우 거래는 추가되지 않음). 값이 잘못됐거나 미등록 카테고리이거나 컬럼이 초과된 **개별 행**은 건너뛰고 `skipped`를 셉니다. 예전 거래 ID가 추가 열에 포함돼 있더라도 사용하지 않고 새 ID를 발급합니다.

`export --out`에는 월(`--month`) 또는 기간(`--from`, `--to`) 중 **한 가지 이상의 필터**가 필요합니다. 기간의 양 끝은 포함됩니다. 예: `export --out ./report.csv --month 2024-01`. 교환용 CSV를 다시 가져오면 **내용 기반 중복 제거 없이** 새로운 거래로 들어갑니다. `--out`으로 내부 4개 파일을 덮어쓸 수는 없습니다.

## 쓰기 안정성과 한계

거래 추가·수정·삭제/반복 규칙·예산·카테고리의 갱신은 **같은 디렉터리의 임시 파일 → 기록 및 `fsync` → `os.replace`** 순서로 처리합니다. 중간에 쓰기가 실패해도 기존 파일을 찢어진 상태로 교체하지 않도록 설계했습니다. 거래 조회/검색은 행을 하나씩 읽지만, **수정·삭제·추가·import는 전체 거래를 다시 쓰므로** 파일이 커질수록 메모리/쓰기 비용이 증가합니다.

실제 추가·수정·삭제·import/export·백업의 호출 순서는 [실행 흐름과 시퀀스 다이어그램](flows.md)을 참고하세요.

> **동시 사용 제한:** `os.replace`는 한 파일의 교체만 보호합니다. 프로세스 간 잠금도, 네 파일 전체를 묶는 트랜잭션도 없습니다. **같은 데이터 폴더에서 쓰기 명령을 동시에 실행하지 마세요.** 서로 다른 프로세스가 같은 최대 ID를 읽어 갱신 손실·ID 충돌이 생길 수 있습니다. 여러 사람이 함께 사용해야 한다면 잠금과 충돌 처리를 설계하거나 [SQLite 이행](format-choice.md#sqlite로-이전한다면)을 고려하세요.

## 백업과 복구

```bash
python -m budget_app backup --data-dir ./data
```

현재 존재하는 저장 파일을 `./data/backups/backup-YYYYmmdd-HHMMSS/`에 **복사**합니다. 같은 초에 다시 실행하면 `-1`, `-2` 접미사로 구분합니다. 복사 중 실패하면 미완성 백업 폴더는 제거합니다. 백업 폴더의 공개는 원자적 교체를 사용하지만, **네 원본 파일을 복사하는 동안 다른 프로세스가 수정한다면 파일 간 일관된 스냅샷은 보장되지 않습니다.**

복구 전에는 앱을 종료하고 현재 `data/` 폴더를 별도로 보관한 다음, 선택한 백업 폴더의 **네 CSV 파일**을 `data/`로 복사하세요. `backup`은 백업만 만들며 자동 복구 명령은 제공하지 않습니다. 각 파일을 읽는 명령에서 해당 CSV의 헤더·행 형식을 검사합니다(백업 자체는 원본을 검증하지 않고 복사합니다).
